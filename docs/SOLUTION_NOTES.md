# Reusable product and private demonstration

**Problem.** Editors repeatedly scan episodic stories to find acquisition creatives. Promo Finder proposes traceable clips for an editor to assess, with exact boundaries, supporting text, a hook and an unresolved ending.

**Product boundary.** The engine operates on normalized timed beats. Input adapters understand format; an explicit policy supplies audience, language, duration and scoring settings. Neither layer contains characters, story events, episode numbers or timestamps copied from a benchmark. Episode identifiers and beat references are derived at runtime. There is no embedded corpus, retrieval of previous benchmark outputs, or fine-tuning on the pack.

**Design.** Code handles parsing, source grounding, timing, speech boundaries and repeat suppression. Models handle narrative judgment. Review sees only the selected source material rather than a logline or the proposer's explanation. Metadata records the complete policy and models. Requests are bounded and resumable. A local adapter and a content-blind offline baseline support development without hosted inference.

**Editor product.** PromoPilot AI is the Streamlit interface around this engine. It adds TXT/JSON/ZIP upload, a no-key fictional recorded demo, score explanations, competing-clip comparison, validated timestamp edits, acceptance/rejection notes, exclusion audits, episode timelines and CSV/JSON downloads. Original model records remain immutable; human-edited cuts are not assigned the old AI score. Session-owned state and temporary model caches are isolated from the public benchmark summary. The allowlisted source bundle includes free-hosting setup for Streamlit Community Cloud.

**Demonstration.** Use Kuku's 50-episode pack as the main private development benchmark. The exact same engine handles original public science-fiction and sports fixtures. The benchmark harness takes expectations and settings from data; it has no special discovery algorithm. Public artifacts contain only code, general criteria, aggregate results and synthetic samples. Do not include real cuts or source excerpts in a public demo or repository.

**Evidence.** The supplied pack parses into 3,727 timed beats and yields 21,421 structurally valid boundary pairs under the benchmark policy. Versioned manifests distinguish historical prototype runs, the generalized version, and any quota-limited partial run. Structural validity is not editorial quality, and neither is proof of ad conversion. Human evaluation and unseen-show testing remain necessary.

**AI usage and failures.** Codex assisted implementation, tests, source inspection and documentation. Live model output exposed invalid duration selections and weak editorial judgments. Those observations led to generic boundary checks and evidence-based review criteria, rather than rules for particular plots or episodes. An API schema compatibility issue was resolved by moving unsupported numeric bounds to local validation. Preserve the actual raw failures privately. Review and understand the code before presenting it.

**Scale.** Partition shows into bounded batches, cache unchanged input/prompt/model combinations, and use a project-wide quota queue before running concurrent workers. Very long individual episodes need a timestamp-preserving chunking adapter, which is not included. Benchmark editor time saved and acceptance before investing in production deployment. Pricing, provider retention and production rights require their own evaluation.

**Walkthrough.** Start with a synthetic public input and the generic configuration. Explain the normalization and legal-cut checks. In an authorized private demonstration, run the same command on Kuku's pack, show coverage and one accepted/rejected output, and describe unmeasured quality/recall. Package only the allowlisted public files. A final two-page submission PDF, private delivery of raw outputs, public code link and human review remain separate submission tasks; none has been published automatically.
